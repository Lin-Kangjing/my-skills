# AI Coding Review（三阶段流水线）

对当前分支的改动做流水线式审查。核心纪律：**每个阶段结束时必须停下来等用户审核，未经批准不得进入下一阶段，更不得擅自修改代码。**

## 范围确定

默认审查当前分支相对 main 的改动（`git diff main...HEAD` + 未提交变更）。用户指定了目录/文件时以指定范围为准。范围确认后先向用户报告一句话："本次审查范围：xxx，共 N 个变更文件"。

## 阶段一：架构总结（只读，不改码）

**目的**：让用户核对实现是否偏离了施工文档的算法与架构，专抓 AI 在文档边界模糊处私自夹带的"优化"。

1. 通读变更文件（必要时向上追溯调用方/被调用方），输出一份简要总结，包含：
   - 实现架构：改动涉及哪些模块，职责如何划分
   - 接口契约：新增/修改的函数签名、参数、返回值、错误处理约定
   - 数据流：数据从哪里来、经过哪些转换、到哪里去
2. **逐条标注可疑点**：凡是文档没明确要求、但代码里"顺手做了"的行为（额外校验、额外抽象、额外兼容层、行为变化），单独列出并说明"文档依据：无 / 有（引用原文）"
3. 输出后**停止**，等用户确认"实现与文档一致"或指出偏差。用户指出偏差后回到代码修正，再重新输出总结，直到用户放行。

## 阶段二：子 Agent 扫描（只报告，不改码）

**目的**：挖逻辑错误、低效算法、冗余调用，报告经人审核后才允许修复。

1. 使用 Task 工具派出多个并行子 Agent（subagent_type=search 或 general_purpose_task），按维度分工，每个 Agent 只返回问题清单：
   - 逻辑错误：边界条件、空值、竞态、状态不一致、错误处理缺失
   - 低效算法：重复计算、N+1 查询、不必要的遍历/渲染
   - 冗余调用：重复请求、重复数据库操作、可合并的 IO
   - 重复代码与冗余抽象：与项目已有实现重复、不必要的包装层
2. 汇总各 Agent 报告，去重合并成一张问题表，每条包含：`编号 | 文件:行号 | 问题描述 | 严重程度(高/中/低) | 建议修法`
3. 输出问题表后**停止**，等用户逐条审核。**只修用户批准的条目**，修完后逐条报告修改结果。

## 阶段三：边界测试循环（修到全绿）

**目的**：用大量边界用例验证实现，出 BUG 就定位修复，循环直到全部通过。

1. 设计测试用例清单，优先覆盖：
   - 边界值：空输入、极值（0、负数、最大值）、单元素集合
   - 异常路径：非法参数、网络失败、权限不足、并发冲突
   - 状态组合：各筛选/开关的全组合中的关键组合
2. 用例清单先给用户过目（用户可增删），确认后写成测试代码并执行
3. 失败的用例：定位根因 → 报告给用户（含修复方案）→ 用户批准后修复 → 重跑全部用例
4. 循环直到全部通过。结束后输出最终报告：通过数/总数、修复清单、遗留风险（如有）

## 中断与恢复

- 任一阶段被用户打断，记住当前阶段编号和已确认的结论，恢复时从断点继续，不重复已完成阶段
- 阶段一、二的产物（总结、问题表）必须完整展示给用户，不得只给结论不给依据

## 禁止事项

- 禁止跳过用户审核直接修改代码
- 禁止在阶段一/二"顺手修复"发现的问题
- 禁止只报告"没问题"而不展示审查依据（审了哪些文件、哪些维度）
- 禁止在阶段三自行决定用例取舍（增删用例必须经用户确认）
